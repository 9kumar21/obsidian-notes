# 🟦 Dockerfile Instructions

| 🟢 **Instruction** | 🔵 **Purpose**                                                                                                                                                                                                                                        | 🟠 **Example**                            |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------- |
| 🟢 **FROM**        | Defines the **base image** for the Docker image. This is always the first instruction in a Dockerfile.                                                                                                                                                | `FROM python:3.12`                        |
| 🟢 **WORKDIR**     | Sets the **working directory** inside the image. All subsequent instructions execute from this directory.                                                                                                                                             | `WORKDIR /app`                            |
| 🟢 **COPY**        | Copies files and directories from the **host** to the **image**.                                                                                                                                                                                      | `COPY . /app`                             |
| 🟢 **ADD**         | More powerful than `COPY`.<br>• Copies files from host to image.<br>• Extracts local `.tar` archives automatically.<br>• Downloads files from URLs.                                                                                                   | `ADD app.tar.gz /app`                     |
| 🟢 **RUN**         | Executes commands **during image build** and creates a new image layer.                                                                                                                                                                               | `RUN apt update && apt install -y nginx`  |
| 🟢 **EXPOSE**      | Documents the port on which the application listens. It does **not** publish the port.                                                                                                                                                                | `EXPOSE 8080`                             |
| 🟢 **ENTRYPOINT**  | - Defines the command that **always executes** when the container starts. <br>- Arguments can be appended using `docker run`.<br>- Can be overridden with `--entrypoint`. [[Day 1, 2, 3 - Troubleshooting#**ENTRYPOINT – Explanation**\|Explanation]] | `ENTRYPOINT ["nginx","-g","daemon off;"]` |
| 🟢 **CMD**         | Specifies the **default command** or arguments for the container. Can be overridden using `docker run <image> <command>`. [[Day 1, 2, 3 - Troubleshooting#**CMD – Explanation**\|Explanation]]                                                        | `CMD ["python","app.py"]`                 |
| 🟢 **ENV**         | Sets **runtime environment variables** available inside the container. [[Day 1, 2, 3 - Troubleshooting#Dockerfile Instruction `ENV` – Deep Dive\|Deep Dive]]                                                                                          | `ENV APP_ENV=production`                  |
| 🟢 **ARG**         | Defines **build-time variables** passed using `--build-arg`.<br><br>[[Day 1, 2, 3 - Troubleshooting#Dockerfile Instruction `ARG` (Deep Dive)\|Deep Dive]] <br>                                                                                        | `ARG VERSION=1.0`                         |
| 🟢 **USER**        | Specifies the user that runs commands and the container.                                                                                                                                                                                              | `USER mvk`                                |
| 🟢 **LABEL**       | Adds metadata to the image (author, version, description, etc.).                                                                                                                                                                                      | `LABEL maintainer="venkat@example.com"`   |
| 🟢 **VOLUME**      | Creates a mount point for **persistent data**.                                                                                                                                                                                                        | `VOLUME /data`                            |
| 🟢 **ONBUILD**     | Runs instructions when the image is used as base image. Or<br>Registers a trigger that runs when the image is used as the **base image** for another build. [[Day 1, 2, 3 - Troubleshooting#ONBUILD\|Deep Dive]]                                      | `ONBUILD COPY . /app`                     |

# 🟦 Most Used Docker Commands

| 🟢 **Command**   | 🔵 **Description**                                                                                                                       |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `docker pull`    | Download an image from a registry.                                                                                                       |
| `docker build`   | Build an image from a Dockerfile.                                                                                                        |
| `docker run`     | Create and start a container.                                                                                                            |
| `docker exec`    | Run a command inside a running container.                                                                                                |
| `docker rename`  | Rename a running or stopped container.**Example:** `docker rename old-name new-name`                                                     |
| `docker tag`     | Assign a new tag to an image.                                                                                                            |
| `docker push`    | Push an image to a registry.                                                                                                             |
| `docker ps`      | List running containers.                                                                                                                 |
| `docker ps -a`   | List all containers (running and stopped).                                                                                               |
| `docker images`  | List all local images.                                                                                                                   |
| `docker start`   | Start a stopped container.                                                                                                               |
| `docker stop`    | Stop a running container.                                                                                                                |
| `docker restart` | Restart a container.                                                                                                                     |
| `docker logs`    | View container logs (`stdout` & `stderr`). Useful for troubleshooting startup issues, runtime errors, and monitoring container activity. |
| `docker inspect` | View detailed information about a container or image. [[Day 1, 2, 3 - Troubleshooting#docker inspect\|Deep Dive]]<br>                          |
| `docker top`     | Display running processes inside a container. [[Day 1, 2, 3 - Troubleshooting#docker top\|Deep Dive]]                                          |
|                  |                                                                                                                                          |

### 🟨 Use Cases of `docker top`

- ✅ See what processes are running inside a container.
    
- ✅ Verify whether your application is actually running.
    
- ✅ Troubleshoot containers behaving unexpectedly.
    
- ✅ View the **PID** and command of running processes.

# 🟦 Build an Image from a Dockerfile

```bash
docker build -t <image-name> -f <dockerfile-path> .
```

### 🟨 Example

```bash
docker build -t python-image .
```

### 🟨 Options

|🟢 **Option**|🔵 **Meaning**|
|---|---|
|`-t`|Assigns a **name** and optional **tag** to the image.|
|`-f`|Specifies a custom Dockerfile path.|
|`.`|Represents the **build context**.|

### 🟨 What is Build Context?

The build context is the directory sent to the Docker daemon during `docker build`.

It includes:

- ✅ Dockerfile
    
- ✅ Application source code
    
- ✅ Configuration files
    
- ✅ All files in the current directory **except those excluded by `.dockerignore`**
    
What is Build Context in Docker?
Anything that is required to build image is called Build Context.

# 🟦 Run a Container

```bash
docker run -d -p <host-port>:<container-port> --name <container-name> <image>
```

### 🟨 Example

```bash
docker run -d -p 8080:5000 --name python-cont python-image
```

# 🟦 Execute Commands Inside a Running Container

### List files

```bash
docker exec python-cont ls
```

### Open an interactive terminal

```bash
docker exec -it python-cont /bin/bash
```

or

```bash
docker exec -it python-cont sh
```

### Run a background process

```bash
docker exec -d python-cont sh -c "while true; do date >> /tmp/date.log; sleep 10; done"
```

> 🟨 **Note:** `-d` (detached mode) is useful for starting long-running background processes inside a running container.
